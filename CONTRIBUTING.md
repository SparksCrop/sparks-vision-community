# Contributing to Sparks Vision

Contributions from human-only and AI-assisted development are welcome. This public repository intentionally excludes customer-facing source, private device control internals, credentials, and sensitive captures.

## Workflow

1. Search existing issues. Open a new issue describing the outcome, mockups, and clear acceptance criteria.
2. A maintainer labels or approves the scope. Prefer small, independent changes.
3. Fork the public repository, create a `feature/` or `fix/` branch, and work locally in your preferred editor (VS Code is optional).
4. Use synthetic data and fake credentials only. Do not upload personal computer screenshots, browser profiles, real user logs, tokens, API keys, or customer data.
5. Submit a pull request that explains the change, tests, documentation and any AI tools used. Identify the responsible human reviewer.
6. A maintainer reviews security, quality, licenses, accessibility and scope before merging.

## Contribution standards

- Keep examples runnable without any personal Windows device, paid subscription or remote account.
- Prefer minimal dependencies with clear licenses; disclose generated or copied material.
- Do not present mock demos as real production capabilities.
- Never publish a security vulnerability exploit in a public issue; see [SECURITY.md](SECURITY.md).
- Avoid introducing code from other repositories unless its license permits reuse with appropriate attribution.
- By contributing, you agree your changes are provided under this repository's MIT license. The maintainer may use MIT-licensed public components in separately licensed commercial products.
- The Sparks Vision name and logos are not licensed for third-party commercial use by the MIT code license.

Review rules in this public repository are defined by maintainers; contributors should not assume submitted work will be accepted or merged. Maintainers can ask for security/compatibility modifications.
